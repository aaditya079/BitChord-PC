<decisions>
## Implementation Decisions

### 1. Crate Architecture
- **Decision:** Separate Cargo workspace with `crates/bitchord-core` (headless audio & Innertube streaming engine) and `crates/bitchord-tauri` (desktop GUI wrapper).
- **Rationale:** Keeps the core engine 100% testable via `cargo test` in terminal without requiring a webview or GUI window.
- **Reversibility:** costly — changing crate boundaries later requires refactoring imports across all features.

### 2. Audio Pipeline & Output Sink
- **Decision:** Pure Rust decoding via `symphonia` with output sink powered directly by `cpal`.
- **Rationale:** Full low-level control over the ring buffer, sample format conversion (f32/i16), WASAPI shared/exclusive mode, and gapless track transitions without intermediate framework overhead.
- **Reversibility:** costly — audio sink architecture defines the core playback pipeline.

### 3. Cipher & Challenge Solving
- **Decision:** Hybrid solver: Fast-path regex AST parser for standard YouTube formats + embedded QuickJS evaluator for dynamic bytecode challenges (n-sig / player.js transforms).
- **Rationale:** Ensures 100% reliability for COPPA / Made-for-Kids tracks and long-term resilience when YouTube modifies player challenge scripts.
- **Reversibility:** reversible — modular solver trait can swap or enhance evaluation backends.

### 4. Buffering & Seeking Strategy
- **Decision:** Hybrid buffering: In-memory lock-free ring buffer for instantaneous zero-lag playback start + background temp disk cache for seamless seeking and replay.
- **Rationale:** Avoids waiting for entire track to download before playing, while eliminating re-download bandwidth when seeking or looping.
- **Reversibility:** reversible — chunk manager handles range streams behind a standard read stream abstraction.

### 5. Extreme Performance & Low-Memory Constraints ("Optimized AF")
- **Decision:** Strict Real-Time Audio Thread Rules & On-the-Fly Decoding:
  - **Zero Allocations on Audio Thread:** The `cpal` output callback operates on a lock-free SPSC ring buffer (`rtrb`). Zero allocations, zero mutex contention, zero file I/O inside the audio processing loop.
  - **Bounded Memory Footprint (Never store raw PCM):** Raw 48kHz 32-bit stereo PCM consumes ~23 MB/minute. Instead of buffering decoded PCM, the engine stores compressed Opus/AAC chunks on disk and decodes only 2-3 seconds ahead of the playhead. Idle RAM ceiling: **< 50MB**.
  - **Zero-Copy Byte Slices:** Use `bytes::Bytes` for network chunk ingestion to avoid heap reallocations.
  - **Compiler Optimizations:** Profile release targets with `opt-level = 3`, `lto = "thin"`, `codegen-units = 1`, and `panic = "abort"`.
- **Rationale:** Guarantees buttery-smooth 60fps desktop experience without stutter even when gaming on an RTX 3050 / budget laptop with strict RAM limits.
- **Reversibility:** costly — memory architectures must be built into data structures from day one.

</decisions>
